## Diagnostics twins (ABI 0.4.0)

**DONE (2026-09-09).** `dualc_field_contour_with_diagnostics` and
`dualc_field_export_with_diagnostics`
were added alongside a flat `DualcDiagnostics` struct, additively (the originals
became forwarders passing `NULL`, so Boletus is unaffected in source and in
binary). Record:
[17/05](../17-code-audit-and-hardening/05-diagnostics-channel.md).

## Unknown parameter keys are rejected (behaviour change, no ABI break)

**DONE (2026-09-11).** `dualc_field_create_from_json` / `_from_expr` (and the
`*_with_meshes` twins) build through the same `buildField` as the CLI, so a node key
the op does not read — previously absorbed silently — now fails the create call with
`DUALC_ERR_GRAPH` and a located message (`unknown parameter 'normal' for 'plane'
(a primitive takes its values positionally …)`). Signatures, structs and codes are
unchanged; only inputs that were already wrong are refused. Boletus is unaffected:
its serializer writes `op`, the node's own params (grouped keys on the seven layout
primitives, `params=[…]` on the rest — `Field.Plane(nx,ny,nz,offset)` is flat) and
`in`, nothing cosmetic. Why and what it caught:
[17/10](../17-code-audit-and-hardening/10-docs-system-screening.md).

## 0.5.1 — the writer's error text reaches `err`; output handles non-inheritable (no ABI break)

**DONE (2026-10-07).** On `DUALC_ERR_IO` both export twins now put the writer's own
`[dualc] error:` line into `err` after a fixed prefix (`export failed: …` /
`tiled STL export failed: …`), read back through `dce::lastError()` (thread-local, cleared
by every `writeField*` on entry); the fixed texts remain the fallback when no line was
left. Behind it, every output file the writers open is non-inheritable and a failed rename
is retried on Windows — the investigation and the evidence are
[17 #52](../17-code-audit-and-hardening/16-windows-rename-race/README.md#52-windows-export-io-flake--the-part-rename-under-an-on-access-scanner).
Signatures, structs and codes are unchanged; `dualc_version()` reads `dualc 0.5.1`.
