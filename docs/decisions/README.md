# Decisions — what was decided, dropped or deferred

The decisions index, so a decision buried in a topic file's chronology is visible from one
place and is not proposed again. Two tables with the same columns: **this page holds every
open or rejected decision** — **DEFERRED** with the trigger that reopens it, **DROPPED** with
the rationale — and [01-settled.md](01-settled.md) holds the decisions **DONE** by choice
(architecture, scope, process) that are not re-litigated. The gate (`decisions-index`) reads
this page: it fails when a `**DEFERRED**` / `**DROPPED**` roadmap entry has no row here, or a
DEFERRED row names no trigger.

One line per row: the ID — `#N` when the decision *is* a tracked roadmap item, else `D-NN`,
one sequence across both tables (given by decision date at birth, never reused; the next
free number is one more than the largest in the folder) — the decision in the present
tense, its status, the date it was taken, and the entry that holds the argument. A trigger
marked † was written here after the fact (2026-09-18, roadmap 19 Phase 4); its roadmap
entry carries a dated pointer back. A DEFERRED decision that lands or is dropped keeps its
row and its ID; only the status cell changes.
